JAXMg

github/flatironinstitute/jaxmg  |  docs  |  paper   

Python · JAX · C++/CUDA · XLA FFI

JAXMg started when both Roeland Wiersema at the Flatiron Institute and I found ourselves bottlenecked by the same problem in completely different domains of computational physics. Roeland needed to solve the large dense linear systems that arise in variational Monte Carlo for quantum many-body physics (see e.g. Wan, Wiersema & Zhang 2026), while I needed them for large-scale Bayesian inference workflows in cosmology. In both cases, there was no way to scale these solves across multiple GPUs without leaving JAX.

JAXMg connects JIT-compiled JAX programs to NVIDIA's cuSOLVERMp. You pass in an ordinary sharded JAX array and get back distributed linear solves and eigenvalue, singular-value and QR decompositions, on matrices approaching the combined memory of every GPU you have. It has since grown into a general tool used across computational science, from the large dense systems behind computational electromagnetics to tensor networks and time-dependent variational Monte Carlo. It is also now fully integrated into NetKet.

REACH GPU Data Analysis Pipeline

private repository (active research)  |  benchmark repository

Python · JAX · BlackJAX · Nested Sampling · Neural Emulation · Multi-GPU

Detecting the global 21-cm signal means pulling a signal of a few hundred millikelvin out from under foregrounds around ten thousand times brighter, all seen through an antenna whose response is never perfectly known. Doing that credibly means modelling and propagating all uncertainties through the whole observational chain, which with conventional simulators simply isn't feasible.

This pipeline makes it tractable for REACH by replacing each expensive simulator with a learned, physically motivated surrogate: a neural emulator for the cosmological signal, a multi-resolution foreground model anchored to radio sky maps, and an antenna beam compressed into a 100-dimensional latent space whose linearity lets its uncertainty be marginalised analytically. Together these run around 107 times faster than the original simulators, turning hundreds of CPU-years of analysis into about two GPU-days.

BayesEoR-v2

private repository (active research)  |  original BayesEoR

Python · JAX · JAXMg · Nested Sampling · Distributed Linear Algebra · Multi-GPU

Recovering the 21-cm power spectrum from interferometric visibilities is fundamentally a problem of scale. Physically motivated, wide-field forward models can require 104–106 parameters, and while analytical marginalisation removes the need to sample them, it shifts the bottleneck to the likelihood itself: each evaluation requires a dense linear solve scaling as 𝒪(N3), precisely the class of problem JAXMg was designed for.

BayesEoR-v2 addresses this by reformulating the inference in a statistically optimal, observation-specific latent space. A noise-informed Karhunen–Loève decomposition of the prior-predictive foreground covariance retains only the modes resolvable above the thermal noise, so the dimensionality of the problem reflects the information content of the data rather than the resolution of the model. Constructed once with JAXMg's distributed solvers, the basis is amortised across all subsequent likelihood evaluations, reducing a full-sky analysis from over 300,000 to under 10,000 parameters and bringing joint power-spectrum and evidence evaluation down to around 20 GPU-minutes.
